# All_Robot — CPS Lab robot models

[![validate-models](https://github.com/Cyber-physical-Systems-Lab/All_Robot/actions/workflows/validate.yml/badge.svg)](https://github.com/Cyber-physical-Systems-Lab/All_Robot/actions/workflows/validate.yml)

These are the simulation models of the robots in the Cyber-physical Systems Lab at Uppsala University. All of them live in this one repository.
The meshes, URDFs, USDs and MJCFs here are the only copies to use. The same URDF works in **RViz2, Gazebo Fortress, MuJoCo and Isaac Sim / Isaac Lab**.
Each simulator can run from its own **conda environment** or its own **Docker image**.

> `Robots_IsaacLab` has been merged into this repo and is archived. See [docs/MIGRATION.md](docs/MIGRATION.md).

## Repository layout

```
All_Robot/
├── robots.yaml                 # registry: the one place that lists every robot
├── robots/<name>/
│   ├── urdf/<name>.urdf        # canonical URDF, package://cps_robot_description/... mesh URIs
│   ├── urdf/standalone/        # generated: relative mesh paths (Isaac Sim, MuJoCo, any non-ROS tool)
│   ├── meshes/                 # DAE / STL  (+ meshes/mujoco/: generated OBJ for MuJoCo)
│   ├── mjcf/<name>.xml, scene.xml   # generated MuJoCo model
│   └── usd/<name>.usd          # generated Isaac USD   (usd/legacy/ = old hand-made USDs)
├── envs/                       # conda envs: env_isaaclab, env_mujoco, env_ros_gz + setup.sh
├── docker/                     # one image per simulator + compose.yaml + run.sh
├── launch/                     # ROS 2: display, all_in_one (RViz2), gazebo (Fortress)
├── isaaclab/                   # Isaac Lab ArticulationCfg, URDF->USD conversion, spawn/check script
├── scripts/                    # normalize_urdf, build_assets, validate, migrate, screenshot_*, make_gallery
├── package.xml, CMakeLists.txt # repo root is the ROS 2 package `cps_robot_description`
└── docs/screenshots/<sim>/      # rviz, gazebo, mujoco, isaac  -> README gallery
```

**Rule:** edit only the canonical `urdf/<name>.urdf` and `meshes/`. Everything else is generated by `scripts/build_assets.py` or `isaaclab/convert_all.sh`.

## 0. Get the repo and pick a runtime

```bash
git clone https://github.com/Cyber-physical-Systems-Lab/All_Robot.git && cd All_Robot
```

| Simulator | Conda environment | Docker image | Needs |
|---|---|---|---|
| Isaac Sim 4.5 + Isaac Lab 2.1 | `env_isaaclab` | `cps/isaaclab:4.5.0-2.1.0` | Ubuntu 22.04, NVIDIA RTX GPU, driver ≥ 535 |
| MuJoCo 3.x | `env_mujoco` | `cps/mujoco:3` | any CPU |
| ROS 2 Humble + Gazebo Fortress + RViz2 | `env_ros_gz` (RoboStack) | `cps/ros_gz:humble-fortress` | any CPU |

**Conda setup.** You need [Miniconda](https://docs.anaconda.com/miniconda/); [mamba](https://mamba.readthedocs.io) is used automatically when it's installed. Each command can be re-run safely.

```bash
bash envs/setup.sh mujoco      # -> env_mujoco
bash envs/setup.sh ros_gz      # -> env_ros_gz  (also colcon-builds this package into ~/cps_ws)
bash envs/setup.sh isaaclab    # -> env_isaaclab (clones Isaac Lab v2.1.0 to ~/IsaacLab, ~25 GB)
```

**Docker setup.** You need Docker with Compose v2. Isaac also needs the [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/install-guide.html).

```bash
docker/run.sh build mujoco ros_gz isaaclab      # once; isaaclab pulls nvcr.io/nvidia/isaac-sim:4.5.0 (~20 GB)
docker/run.sh <mujoco|ros_gz|isaaclab> [cmd]    # repo is mounted, X11 + GPU forwarded
```

## 1. ROS 2 Humble · RViz2

```bash
# conda
conda activate env_ros_gz
ros2 launch cps_robot_description display.launch.py robot:=nova5_2f85
ros2 launch cps_robot_description display.launch.py robot:=mycobot_280_pi variant:=with_pump
ros2 launch cps_robot_description all_in_one.launch.py                 # all robots side by side

# docker
docker/run.sh ros_gz ros2 launch cps_robot_description display.launch.py robot:=go2
```

With a system ROS install instead, put the repo in a colcon workspace and run `colcon build --packages-select cps_robot_description`.

## 2. Gazebo Fortress

```bash
# conda
conda activate env_ros_gz
ros2 launch cps_robot_description gazebo.launch.py robot:=nova5_2f85
ros2 launch cps_robot_description gazebo.launch.py robot:=go2

# docker
docker/run.sh ros_gz ros2 launch cps_robot_description gazebo.launch.py robot:=nova5_2f85
```

- Arms (`fixed_base: true`) are welded to the world. Mobile robots spawn free at `spawn_z`.
- The launch file sets `IGN_GAZEBO_RESOURCE_PATH` so that `package://cps_robot_description/...` resolves.
- Only the model is spawned, with no controllers. To drive joints, add `gz_ros2_control` tags.

## 3. MuJoCo 3.x

The MJCF files are generated from the canonical URDFs. DAE meshes are converted to OBJ, because MuJoCo can't read DAE.

```bash
# conda
conda activate env_mujoco
python scripts/build_assets.py --mujoco                       # generate (all robots, or list names)
python -m mujoco.viewer --mjcf=robots/nova5_2f85/mjcf/scene.xml

# docker
docker/run.sh mujoco python scripts/build_assets.py --mujoco
docker/run.sh mujoco python -m mujoco.viewer --mjcf=robots/nova5_2f85/mjcf/scene.xml
```

What the generator adds:

- A `freejoint` for mobile robots.
- `equality` constraints for URDF `<mimic>` joints (grippers).
- A `position` actuator on every joint.
- `scene.xml`, with a floor and a light.

Use `robots/<r>/mjcf/<r>.xml` with `<include>` in your own scenes.

## 4. Isaac Sim 4.5 / Isaac Lab 2.1

```bash
# conda  (envs/setup.sh set ISAACLAB_PATH and CPS_ROBOTS_PATH inside the env)
conda activate env_isaaclab
bash isaaclab/convert_all.sh                                   # URDF -> robots/<r>/usd/<r>.usd
python isaaclab/spawn_robot.py --robot nova5_2f85              # view + wiggle joints
python isaaclab/spawn_robot.py --robot all --check --headless  # PASS/FAIL table

# docker  (inside the container, Isaac Lab is at /workspace/isaaclab)
docker/run.sh isaaclab bash isaaclab/convert_all.sh
docker/run.sh isaaclab /workspace/isaaclab/isaaclab.sh -p isaaclab/spawn_robot.py --robot nova5_2f85
```

On its first start, Isaac Sim pulls extensions and compiles shaders, which takes about 10 minutes. With Docker, these are cached in named volumes.

**Isaac Sim GUI only:** go to **File → Import** and pick `robots/<r>/urdf/standalone/<r>.urdf`. Importer options:

- *Fix Base Link*: on for arms.
- *Joint Drive*: Position.
- *Merge Fixed Joints*: off.

**In your own Isaac Lab project:**

```python
import os, sys; sys.path.append(os.path.join(os.environ["CPS_ROBOTS_PATH"], "isaaclab"))
from cps_robots_cfg import make_cfg
robot_cfg = make_cfg("nova5_2f85").replace(prim_path="{ENV_REGEX_NS}/Robot")
```

`make_cfg` resolves the USD in this order:

1. `usd/<r>.usd` (regenerated).
2. `usd/legacy/...` (the old hand-made USD).
3. For `go2`, Isaac Lab's built-in `UNITREE_GO2_CFG`.

The actuator gains are in `ACTUATORS` in `isaaclab/cps_robots_cfg.py`.

## Validation

```bash
python scripts/validate.py -v               # static: tree, meshes exist, inertia, limits, no /home paths
python scripts/validate.py --mujoco         # in env_mujoco / docker mujoco
python scripts/validate.py --gazebo         # in env_ros_gz / docker ros_gz (runs `ign sdf -p`)
python isaaclab/spawn_robot.py --robot all --check --headless   # in env_isaaclab / docker isaaclab
```

A cell in the status table becomes ✅ only after a lab member has:

1. Run the matching check.
2. Opened the robot in the simulator and seen that the meshes are in the right place and the joints move the right way.

Write the simulator version and conda/Docker in the PR description.

## Screenshots

The gallery above is generated, so don't paste images into the README by hand.

```bash
bash scripts/capture_all.sh                  # all four simulators via Docker, then refresh the gallery
bash scripts/capture_all.sh mujoco isaac     # a subset
```

Or, inside each conda environment:

| Simulator | Command (from the repo root) | How it renders |
|---|---|---|
| RViz2 | `bash scripts/screenshot_ros.sh rviz` (env_ros_gz) | Xvfb virtual display |
| Gazebo | `bash scripts/screenshot_ros.sh gazebo` (env_ros_gz) | Xvfb + software OpenGL |
| MuJoCo | `MUJOCO_GL=egl python scripts/screenshot_mujoco.py` (env_mujoco) | offscreen renderer |
| Isaac Sim / Lab | `python isaaclab/spawn_robot.py --robot all --screenshot --headless` (env_isaaclab) | RTX camera sensor |

Then run `python3 scripts/make_gallery.py` and commit `docs/screenshots/` together with `README.md`.

**From CI, without installing anything:** every push to `unified-models` does this automatically. On other branches, go to GitHub → Actions → *validate-models* → *Run workflow* and tick `commit_screenshots`. This captures RViz2, Gazebo and MuJoCo, commits the images, the gallery and the generated MuJoCo files. Isaac needs an RTX GPU, so capture it locally.

To change the framing of a robot, edit `camera:` in `robots.yaml`. All four simulators use it.

## Adding a new robot

1. Put the files in `robots/<name>/meshes/` and `robots/<name>/urdf/<name>.urdf`.
2. Add an entry to `robots.yaml` (copy an existing one).
3. `python scripts/normalize_urdf.py <name>`: fixes mesh URIs and fills missing inertia and limits. Every change is listed.
4. `python scripts/build_assets.py --mujoco <name>`, then `bash isaaclab/convert_all.sh <name>`.
5. `python scripts/validate.py -v <name>`. Add a row to the status table above. CI checks the rest.
6. Add a `camera:` entry in `robots.yaml` and capture screenshots (see [Screenshots](#screenshots)).

## Known issues / TODO

- **Placeholder physics.** These links had no `<inertial>`, so they got a placeholder mass from `normalize_urdf.py`, marked with an XML comment:
  - myAGV
  - myCobot 280 (all variants)
  - the `mycomb` arm

  Several joints also had `effort="0" velocity="0"` and were given the defaults from `robots.yaml`. See `docs/normalize_report.md`. Replace these with CAD or datasheet values before using the models for dynamics or RL.
- **myAGV** is a visual shell with no wheels or drive.
- **DAE → OBJ conversion** applies the Collada `<unit>` scale and up-axis. Compare one robot in MuJoCo against RViz to check orientation.
- Large meshes (>10 MB DAE) slow down Gazebo and MuJoCo collision. Simplified collision meshes would help.
- **RTX 50-series GPUs** need a PyTorch nightly build in `env_isaaclab`; see the note in `envs/env_isaaclab.yml`.
